# Эмулятор оболочки ОС (вариант 18)

Практическая работа по дисциплине «Конфигурационное управление», РТУ МИРЭА.
Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом (GUI).

Язык реализации — Python 3.9+, интерфейс — Tkinter (входит в стандартную
поставку Python), сторонние зависимости не нужны.

## Запуск

Windows: `run.bat [параметры]`, Linux/macOS: `./run.sh [параметры]`.

## Тесты

```
python -m unittest discover -s tests -v
```

или `test.bat` в Windows.

## Структура

```
src/
  main.py           — GUI (окно, ввод/вывод), точка входа
  config.py         — параметры командной строки
  shell.py          — сеанс: разбор строки, вызов команд, журнал
  shell_parser.py   — разбор строки и раскрытие переменных окружения
  commands.py       — реализация команд
  script_runner.py  — выполнение стартового скрипта
  xml_logger.py     — журнал вызовов команд в XML
tests/              — модульные тесты (unittest)
scripts/            — скрипты ОС (.bat/.sh) для проверки этапов
scripts/startup/    — стартовые скрипты эмулятора
```

## Параметры командной строки

```
python src/main.py [--vfs PATH] [--log PATH] [--script PATH]
```

| Параметр | Назначение |
|---|---|
| `--vfs PATH` | путь к физическому расположению VFS; имя файла без расширения — имя VFS |
| `--log PATH` | путь к журналу вызовов команд в формате XML |
| `--script PATH` | путь к стартовому скрипту |
| `--help` | справка по параметрам |

При запуске все заданные параметры выводятся в консоль и в окно
(отладочный вывод).

## Этап 1. REPL

Минимальный прототип: окно с полем вывода и строкой ввода команд.
Команды `ls` и `cd` пока являются заглушками и выводят своё имя и аргументы.

### Возможности

- **GUI**: окно Tkinter, заголовок окна содержит имя VFS
  (`Эмулятор оболочки — vfs`), приглашение к вводу — `vfs$`.
- **Парсер** (`src/shell_parser.py`):
  - слова разделяются пробелами;
  - раскрываются переменные окружения реальной ОС: `$HOME`, `${USERNAME}`;
  - неизвестная переменная заменяется пустой строкой, как в sh;
  - в двойных кавычках `"..."` переменные раскрываются, пробелы сохраняются;
  - в одинарных кавычках `'...'` текст берётся буквально;
  - соседние фрагменты склеиваются: `a"b c"'d'` → `ab cd`;
  - незакрытая кавычка — ошибка разбора.
- **Команды** (`src/commands.py`):

  | Команда | Описание | Ошибки |
  |---|---|---|
  | `ls [-l\|-a\|-la\|-al] [путь...]` | заглушка, выводит имя и аргументы | неизвестная опция |
  | `cd [путь]` | заглушка, выводит имя и аргументы | больше одного аргумента |
  | `exit [код]` | закрывает эмулятор | нечисловой код, больше одного аргумента |

- **Обработка ошибок**: неизвестная команда, неверные аргументы, ошибка
  разбора строки. Ошибки выводятся красным цветом.
- **История команд**: стрелки ↑ / ↓ в строке ввода.

### Пример сеанса (этап 1)

Переменные окружения взяты из реальной ОС (Windows):

```
vfs$ ls
ls: аргументы []
vfs$ ls -l $HOME
ls: аргументы ['-l', 'C:\Users\Василий']
vfs$ cd "$HOME/My Docs"
cd: аргументы ['C:\Users\Василий/My Docs']
vfs$ cd '$HOME'
cd: аргументы ['$HOME']
vfs$ ls ${USERNAME}_dir $NOPE end
ls: аргументы ['Василий_dir', 'end']
vfs$ cd a b
cd: слишком много аргументов
vfs$ ls -z
ls: неверная опция '-z'
vfs$ foo bar
foo: команда не найдена
vfs$ ls "unclosed
ошибка разбора: незакрытая кавычка "
vfs$ exit abc
exit: требуется числовой аргумент: abc
vfs$ exit
```

## Этап 2. Конфигурация

### XML-журнал

Каждый вызов команды записывается в файл, заданный `--log`. Событие
содержит время, имя пользователя ОС, команду, аргументы и сообщение об
ошибке (пустое, если ошибки не было). Существующий журнал дополняется.

```xml
<log>
  <event time="2026-09-22T11:55:59" user="vasya">
    <command>cd</command>
    <args>
      <arg>a</arg>
      <arg>b</arg>
    </args>
    <error>cd: слишком много аргументов</error>
  </event>
</log>
```

### Стартовый скрипт

Текстовый файл в UTF-8, одна команда в строке. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Каждая команда выводится в окно вместе
с приглашением, затем её результат — как при ручном вводе. На первой
ошибке выполнение прекращается с сообщением
`Скрипт остановлен: ошибка в строке N`. Команда `exit` в скрипте
закрывает эмулятор.

### Скрипты ОС для проверки параметров

Лежат в `scripts/`, для каждого есть версия `.bat` (Windows) и `.sh`:

| Скрипт | Что проверяет |
|---|---|
| `stage2_no_params` | запуск без параметров |
| `stage2_all_params` | все параметры; скрипт `startup/stage2.txt` останавливается на ошибке |
| `stage2_log_only` | только журнал, команды вводятся вручную |
| `stage2_script_exit` | скрипт с `exit` закрывает окно |
| `stage2_bad_script` | несуществующий файл скрипта |
| `stage2_help` | справка `--help` |
